# Web 管理后台筛选选项与表单对齐细化

## 背景

安全审计筛选仍要求用户理解内部事件 key 和用户 ID，系统诊断输入样式不统一，桌面安全审计三列字段因说明行数量不同而错位。

## 目标

用可读选项替代内部值输入，统一筛选控件视觉规范，并保证桌面字段对齐。

## 范围边界

仅改变 Web 展示和筛选输入方式；提交给后端的 `action`、`actor_user_id` 等参数保持不变。

## 模块设计

- 事件类型使用中文或英文友好名称的固定选项，值仍为真实审计 action。
- 操作者从有权限读取的用户列表生成账号选项。
- 审计卡片标题使用友好事件名，展开详情保留原始技术字段。
- 诊断与审计筛选统一字体、高度、内边距和辅助说明行。

## 数据流

进入安全审计页时并行加载审计事件和可见用户；选择项把真实 action 或用户 ID 写入现有筛选状态。

## 测试方案

覆盖友好事件选项、操作者账号选项和事件标题展示，并运行完整前端检查与构建。

## 验收标准

- 筛选界面不要求输入内部事件 key 或用户 ID。
- 事件和账号选项可直接理解。
- 系统诊断输入框样式一致。
- 桌面安全审计三列控件上下对齐。
