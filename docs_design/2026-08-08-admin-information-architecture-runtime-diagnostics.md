# 管理后台信息架构与运行诊断改版设计

## 背景

当前管理后台把系统健康、Capability、原始 Turn Activity、系统事故和安全审计并列展示。“近期任务活动”直接暴露底层字段，缺少任务、账号、错误和进入详情的上下文；安全审计又占据一级导航，容易与 Trace 排错能力混淆。

## 目标

让管理后台围绕日常运维组织：概览回答系统是否正常，运行诊断回答哪里出错，安全审计降级为高级安全账本。

## 范围边界

- 调整 Web 管理后台信息架构、运行记录展示和必要的查询字段。
- 保留现有账号、角色、诊断和审计权限边界。
- 不把完整 raw trace、Tool 参数、输出、Secret 或其它敏感内容暴露给前端。
- 不删除底层 Security Audit 能力和历史数据。

## 模块设计

### 一级导航

- 概览
- 账号管理
- 角色与权限
- 运行诊断
- 高级设置

安全审计进入高级设置，不再作为日常一级运维入口。

### 概览

展示 Gateway、模型、渠道、近期失败和当前事故数，并给出进入运行诊断的操作入口。

### 运行诊断

- 事故和错误优先。
- 系统诊断筛选保留账号、Session、组件、错误码和状态。
- 最近运行默认只看失败，可切换全部、失败、运行中、已停止和已完成。
- 运行记录补充 Session 标题、账号、渠道、错误码、开始时间和自动换算耗时。
- 时间线继续只返回白名单脱敏字段。

### 高级设置

承载低频安全审计，保留账号、敏感事件、结果、时间筛选、分页和导出。

## 数据流

`turn_runs` 与 `session_index`、`users` 在管理读取边界关联，生成可读的最近运行记录；系统事故继续由 `SystemDiagnosticsService` 聚合；安全审计继续读取 `audit_events`。

## 测试方案

- 运行查询返回账号和 Session 标题。
- 导航和页面权限保持正确。
- 最近运行默认失败筛选、状态切换和耗时展示正确。
- 安全审计只出现在高级设置中。
- 执行 Ruff、Pytest、前端 lint、typecheck、Vitest 和生产构建。

## 验收标准

1. 一级导航不再出现“安全审计”，而是“高级设置”。
2. 系统监控更名为运行诊断并以异常排查为主。
3. 最近运行记录能说明哪位账号、哪个任务、哪个渠道发生了什么。
4. 安全审计仍可在高级设置中查询和导出。
5. 不扩大现有权限和敏感数据暴露范围。
