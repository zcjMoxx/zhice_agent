# 工作流可读输出与编辑器可用性设计

## 背景

真实运行 `4f41d00c-8eba-46e7-ac37-981e1985dd27` 已执行“获取信息 → 智能处理 → 发送结果”，智能处理也生成了正常中文摘要，但发送节点仍保留插入前的旧 `source_ref`，最终继续发送天气接口原始 JSON。编辑器同时缺少节点详情收起和连线删除入口，运行历史区域过矮且重复展示最终结果与错误码，普通用户难以理解和操作。

## 目标

- 连线成为步骤间数据流的唯一用户心智：智能处理和发送结果自动使用直接上一步，不要求用户选择内部变量。
- 执行器以真实前驱输出覆盖遗留 `input`/`source_ref`，保证旧草稿和非前端调用也不会沿用过期引用。
- 智能处理默认输出可直接阅读和发送的中文内容，高级呈现选项保持可选并默认收起。
- 节点详情可收起和重新展开；连线可点击或通过显式删除按钮移除。
- 运行历史增加高度，右侧仅展示本次执行步骤，不再重复最终结果或展示内部错误码。

## 范围边界

- 不改变固定节点目录、DAG 安全校验、权限、连接 ownership 和不可变发布版本。
- 不在输出节点中隐式增加新的 LLM 调用；可读内容仍由画布中的智能处理节点产生。
- 不代用户再次执行真实邮件工作流，避免重复外部副作用。

## 模块设计与数据流

1. 前端根据每个节点唯一的直接入边生成 `${nodes.<source>.output}`；智能处理写入 `input`，发送结果写入 `source_ref/body`。表单只说明“自动使用上一步”。
2. 执行器在每个节点运行前读取 DAG 前驱；唯一前驱存在时，使用已经完成的真实输出覆盖智能处理和输出节点的遗留引用。
3. 详情面板收起后释放右侧宽度，画布提供明确的重新展开按钮。
4. 连线中点提供插入和删除两个操作；键盘 Delete 也可删除当前选中连线。
5. 运行历史展开高度提升，左侧选择运行，右侧只显示节点名称、中文状态和时间。

## 测试方案

- 后端回归：发送节点即使保留旧查询引用，也必须采用直接前驱智能处理的中文结果。
- 前端工具测试：唯一前驱引用推导、智能处理输入和发送结果引用同步。
- 前端 lint、typecheck、Vitest 和生产构建。
- 浏览器只读/无副作用验收：详情收起与展开、连线删除入口、运行历史布局和中文提示；不点击立即运行。

## 验收标准

- 当前问题画布下一次保存/发布时，发送节点自动引用智能处理结果。
- 用户无需看到或选择 `${nodes...}` 等内部变量。
- 节点详情可一键收起并恢复；每条连线都有清晰删除入口。
- 展开的运行历史明显高于旧版，右侧只保留执行步骤。
- 后端与前端相关测试、静态检查和构建全部通过，网关健康。
