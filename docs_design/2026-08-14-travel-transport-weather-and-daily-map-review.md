# 旅行交通、天气与按天地图改进审查稿

> 状态：仅记录、等待用户审查。当前不继续探索外部平台，不修改代码，不启动服务。

## 背景

对现有“重庆到贵阳六日计划”的只读核对发现：高德公交查询并非完全未执行，而是查询结果没有被当前计划结构和前端完整接住；天气和交通卡片直接暴露内部枚举或缺失字段占位；地图将全部日期的地点与路线同时绘制，长行程阅读混乱。

本记录用于固定已确认事实、待定外部能力和建议改动范围，等待用户后续通知后再决定是否实施。

## 已确认事实

### 交通占位符

交通方案卡片当前固定渲染：

```text
duration · price/price_note · status
```

截图对应计划的 `transport_options` 只有 `mode`、`summary`、`source`，缺少上述三个字段，因此前端回退为：

```text
— · — · —
```

这不是有业务含义的符号，而是缺失字段被逐项显示后的结果。

### 高德公交查询

关联旅行 Session 实际调用了：

```text
mcp__amap-maps__maps_direction_transit_integrated
```

该轮同时发起五个公交综合路线请求，其中四个成功，一个返回：

```text
CUQPS_HAS_EXCEEDED_THE_LIMIT
```

这表明本轮触发了高德侧并发、QPS 或套餐额度限制。成功结果已经包含总耗时、总步行距离、公交/地铁分段、线路、上下车站、途经站和路线信息，但最终计划只保留了简化的方式、起终点、耗时、距离和来源。

截图对应计划最终共有八段市内路线：三段写为高德公交查询，五段仍是 `model_estimate`；所有 `path` 均为空。详细公交换乘结果没有成为可展示、可审计的计划数据。

### 打车能力

当前运行只激活了高德公交综合路线，没有同时激活驾车路线，因此没有查询驾车 ETA、驾车轨迹或 `taxi_cost` 参考价。

高德标准路径规划可以提供出租车参考费用，但不等于高德打车、滴滴或花小猪的实时成交价、附近车辆数量或真实可叫车状态。地图路线能力与网约车交易能力必须分开标注。

### 天气 `LIVE · —`

`LIVE` 是内部 `freshness=live`，表示预报窗口内近期查询的动态数据，不表示持续推送或实时直播。当前前端对 live 证据使用约六小时的刷新判断。

截图对应天气证据实际来自 Open-Meteo，并有 `data_as_of`；但 `weather_summary` 没有复制 `provider` 和更新时间，前端因此显示 `LIVE · —`。

### 地图混乱

当前地图把所有日期的活动点、真实路径和顺序参考线一次性绘制，并用全部覆盖物执行自动缩放。地点编号跨天连续，下方每日摘要与地图没有交互联动，因此六日计划会同时出现大量点和线。

## 待定外部能力

### 花小猪或滴滴账号模拟查询

该路线暂不探索，等待用户后续明确通知。

如果以后评估，只考虑用户授权的交互式账号会话，例如由用户自行扫码登录、在可见浏览器中查询；不要求用户在聊天中提供明文密码、Cookie、短信验证码或长期令牌。

评估前必须先确认：

- 平台服务条款是否允许自动化查询。
- 是否存在验证码、设备风控、频率限制和账号封禁风险。
- 查询结果是否允许用于第三方旅行规划展示。
- 是否能稳定取得车型、预计等待时间、动态价格和时间戳。
- 登录态如何由用户控制、撤销和清理。

如果合规性、稳定性或维护成本不满足要求，则放弃账号模拟，不影响高德参考价与跳转方案。

### 腾讯位置服务

腾讯位置服务可作为未来备用路线源，但当前不接入、不申请 Key。后续如启用，仅在高德限流、失败或覆盖不足时查询，避免两个地图源对相同路段无差别重复调用。

## 建议改动范围

### 1. 清理无意义占位符

- 交通卡片按实际存在的字段展示，不再拼出 `— · — · —`。
- 缺少动态价格时显示明确文案，例如“价格未实时查询”，而不是横线。
- 来源字段单独展示为“高德公交路线”“12306 查询”或“模型估算”。
- 模型估算与外部查询使用不同视觉标签。

### 2. 建立结构化交通模型

将当前任意对象形式的 `transport_options` 收紧为稳定结构，建议至少包含：

```text
scope              跨城 / 市内 / 当日接驳
mode               高铁 / 公交 / 地铁 / 步行 / 驾车 / 打车参考
from / to
duration_minutes
distance_km
price_cny / price_kind
status
provider
retrieved_at
freshness
source_kind
```

公交综合路线另保留：

```text
walking_minutes
walking_distance
transfers
lines[]
boarding_stop
alighting_stop
entrance / exit
stations
polyline
```

打车参考必须包含 `price_kind=estimate`，不得与真实订单价格混用。

### 3. 调整高德查询调度

- 不再对同一高德服务一次并发五个路线请求。
- 按天处理相邻活动路段，每次一至两个有界请求。
- 对 QPS/额度错误使用退避和限次重试，不立即并发补发。
- 同一结果可复用时建立 Session 内短期缓存，避免重复算路。
- 优先查询当天真正需要展示的路段，其余日期按顺序补齐。
- 保存成功、失败、限流和模型降级的逐段状态。

### 4. 同一路段提供交通对比

对适合对比的市内路段，可查询并展示：

- 公交/地铁推荐方案。
- 驾车 ETA 与出租车参考价。
- 距离较短时的步行方案。

不要求所有路段同时查询所有方式。根据距离、时间、用户偏好和天气决定查询组合，控制调用量。

### 5. 强化完成门槛

- 单次地点搜索或地理编码成功不能代替路线查询成功。
- 计划引用“高德公交查询”时必须关联真实路线结果或明确降级。
- 每个非步行的相邻活动路段应有已查询路线，或标为待复核/模型估算。
- 高德调用成功但结果未写入计划时，不得视为交通信息完整。
- 公交详情、路线轨迹和来源时间必须能从保存计划恢复。

### 6. 天气文案与结构

将 `weather_summary` 收紧为至少包含：

```text
date
condition
temperature_range
precipitation_probability
provider
retrieved_at
data_as_of
freshness
```

用户侧将内部枚举本地化：

- `live` -> “最新预报”
- `historical` -> “历史气候参考”
- `snapshot` -> “查询快照”
- `estimate` -> “估算”
- `unknown` -> “待确认”

展示示例：

```text
最新预报 · Open-Meteo
更新于 8月14日 17:11
```

### 7. 地图按天切换

建议地图顶部提供：

```text
总览 | Day 1 | Day 2 | Day 3 | ...
```

- 默认打开 Day 1。
- 每天地点编号从 1 重新开始。
- 地图只绘制当前日的地点和路线。
- 切换日期时替换覆盖物并重新缩放。
- 点击时间线某一天时同步切换地图。
- “总览”只展示跨城和区域级关系，不叠加全部市内细线。
- 真实路线用实线；只有地点顺序时用虚线，并标注“顺序参考，并非导航路线”。
- 当前日可切换“推荐、公交地铁、打车参考”，但仅展示实际查询过的方式。

### 8. 前端信息层级

交通信息建议拆成三层：

1. 跨城抵达与返程。
2. 每日市内移动。
3. 当前选中路段的换乘/打车详情。

避免把“高铁”“整个城市的市内交通概述”和“单个古镇往返路线”放在同一级卡片中比较。

## 建议实施顺序

### 第一阶段：展示和结构收敛

- 去除空占位符。
- 本地化 freshness。
- 补齐 provider 与更新时间。
- 地图增加按天切换，但继续兼容旧计划。

### 第二阶段：交通数据闭环

- 新增结构化公交换乘和打车参考字段。
- 调整高德路线查询调度、限流退避与缓存。
- 强化逐段路线完成门槛和来源关联。

### 第三阶段：备用源与账号方案

- 评估腾讯位置服务作为失败备用源。
- 仅在用户再次明确授权后，评估花小猪/滴滴账号会话模拟；不满足合规和稳定性要求则终止。

## 测试建议

- 缺少 duration/price/status 时不出现连续横线。
- `live` 天气显示中文含义、provider 和更新时间。
- 高德五个待查询路段不会同时并发发出。
- QPS 错误退避、限次重试，并保留其他成功结果。
- 公交结果能保存并恢复线路、站点、换乘和轨迹。
- 模型估算不会伪装成地图查询。
- 六日计划默认只显示第一天地图，日期切换不残留上一天覆盖物。
- 旧计划无 polyline 时仍显示每日地点顺序和明确虚线说明。

## 验收标准

- 页面不再出现无语义的 `— · — · —` 或 `LIVE · —`。
- 每段市内交通都能区分真实查询、估算和待复核。
- 高德公交结果中的关键换乘信息可阅读、可保存、可恢复。
- 高德并发限制不再因同批大量路线请求被主动触发。
- 地图默认按天阅读，用户可清楚知道当前查看的是第几天。
- 未经用户后续通知，不开展花小猪/滴滴账号模拟探索。
