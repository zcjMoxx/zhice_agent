# 工作流字段文案与运行方式分组设计

## 背景

工作流触发器把固定间隔、每天、每周、每月和单次定时全部平铺在“什么时候运行”中，选项重复且视觉冗长。结果出口使用“保留在工作流运行结果中”“使用我的 SMTP 发送”等长文案，也容易让用户误以为只有不外发时才保存执行结果。

## 目标

- 将运行方式收敛为三个等长主选项：手动触发、周期运行、定时一次。
- 仅在选择周期运行后显示固定间隔、每天运行、每周运行、每月运行。
- 将结果出口统一为简短渠道语义，并明确所有结果都会保存在执行记录中。
- 保持现有工作流 JSON、调度编译和历史草稿兼容。

## 范围边界

- 只调整前端字段分组、文案、模板节点默认名称和对应测试。
- 不修改 `schedule_mode` 的 `manual/every/daily/weekly/monthly/once` 持久化值。
- 不改变保存、发布、试运行或外部投递行为。

## 模块设计

触发器第一层“运行方式”映射为：

- 手动触发 -> `manual`
- 周期运行 -> `every/daily/weekly/monthly`
- 定时一次 -> `once`

选择周期运行时出现第二层“重复周期”。已有周期草稿保留原有具体周期；从其他模式切入周期运行时默认每天运行。

结果出口“结果去向”统一为：仅作记录、微信通知、QQ 通知、邮箱通知、SMTP 发送。下方固定说明所有结果均保存在执行记录中，通知选项会额外发送到对应渠道。

## 数据流

```text
运行方式主选项
  -> 前端映射到现有 schedule_mode
  -> 既有 syncScheduleConfig
  -> manual/date/interval/cron

结果去向文案
  -> 现有 delivery_mode
  -> 既有工作流节点类型与投递 Provider
```

## 测试方案

- 验证运行方式第一层只展示三个主选项。
- 验证选择周期运行后出现四种重复周期。
- 验证选择定时一次后展示单次说明并隐藏重复周期。
- 验证结果去向新文案和统一执行记录说明。
- 运行前端全量测试、Lint、类型检查和生产构建。

## 验收标准

- 第一层选项短且整齐，不再重复“固定时间”。
- 历史工作流打开后仍正确落入对应主选项和周期子选项。
- 用户明确知道所有结果都会进入执行记录。
- SMTP 与通知邮箱仍能清楚区分。
