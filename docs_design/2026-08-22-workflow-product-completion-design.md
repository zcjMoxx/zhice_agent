## 背景

现有工作流已经有独立运行时、画布、调度、查询、智能处理、条件、模板和邮件节点，但普通界面仍沿用了后端节点分类：外部工具查询、外部工具操作、内容模板、官方通知、个人邮件并列出现，查询功能按 MCP 来源分组。用户需要理解技术分类，且空的操作目录和未配置的个人邮箱会形成死路。

本轮不在现有页面上继续增加说明，而是把它收敛成一套完整产品：用户只表达“什么时候、获取什么、怎么处理、如何判断、结果去哪里”；工具名、MCP 来源、模板变量、连接凭据和内部节点类型全部由系统管理。

## 目标

- 总览是完整应用首页，单个工作流才进入画布。
- 普通用户节点库固定为开始、获取信息、智能处理、条件分支、发送结果。
- 查询按用户任务呈现，不按服务商或 MCP 来源组织。
- 内容模板合并到发送结果；润色只是智能处理的一种任务。
- 无真实 action tool 时隐藏外部操作；以后也只动态展示审核过、当前用户可用的具体动作。
- 邮件账号在设置中心完成连接、状态、测试发送、重新授权和删除闭环。
- 能力是否可用以当前用户真实目录、连接状态和调用结果为准，不能以代码存在或进程启动代替。
- 旧工作流继续读取和运行，编辑时使用新语义展示，不破坏存量数据。
- 普通 viewer、developer、admin 默认可以管理个人工作流、定时、自我通知和本人邮箱连接；外部写操作、社交发布和跨用户管理仍保留独立高权限。

## 范围边界

- WorkflowRuntime 继续独立于 AgentLoop 和聊天 Session。
- 后端继续保留 `schedule_trigger`、`mcp_query`、`mcp_action`、`llm_transform`、`template`、`condition`、`official_notification`、`personal_email` 作为稳定协议。
- 不加入任意代码、Shell、任意 HTTP、循环或子工作流。
- 不为了扩充节点数量接入没有明确场景、授权和结果确定性的写操作。
- 正常登录用户管理自己的工作流和连接；敏感动作仍经过 RBAC、连接所有权、发布校验和审计。

## 真实能力结论

2026-08-22 使用当前运行配置完成 MCP 启动和代表性只读调用：

- Open-Meteo：城市天气可用且无需用户 API Key；中文详细地址需要高德兜底。
- 高德地图：文本地点搜索可用，保留为地点搜索和天气地址解析的内部能力。
- Tavily：网页搜索可用，保留为“搜网页”。
- 12306 社区只读 MCP：站名转码和余票查询可用，必须标明数据需以铁路官方渠道为准，不能提供订票或支付。
- 小红书只读：真实页面搜索返回 10 篇公开笔记，但登录状态与搜索状态曾存在不一致；保留入口，以实际测试查询为准，结构化失败不得显示成成功，预览超过 30 秒返回明确超时提示。
- MCP action allowlist 为空：不展示“外部工具操作”。
- Gmail、Microsoft、SMTP 的协议实现与单元测试存在，但当前没有连接主密钥、OAuth 客户端或官方 SMTP，也没有真实收件证据；完成设置入口和测试发送后仍需凭据做最终 E2E。

## 产品信息架构

### 工作流首页

- 应用级头部、用途说明、新建入口。
- 场景模板只展示当前真实可用能力支持的模板。
- 我的工作流卡片展示名称、用途、状态、最近运行、下次执行、编辑和删除。
- 空状态同时提供从模板创建和空白创建。

### 工作流编辑页

普通节点库：

1. 开始：手动、每天、每周、每月、间隔、单次。
2. 获取信息：查天气、查火车票、搜地点、搜网页、搜小红书。
3. 智能处理：摘要、重点、润色、分类、自定义。
4. 条件分支：选择前序结果、判断方式和比较值。
5. 发送结果：保留为工作流结果、官方通知、个人邮件。

当真实 action catalog 非空时，才增加动态的“执行操作”，并直接列出“创建日程”等具体任务，绝不展示 MCP Action 或泛化工具调用。

### 设置中心

“渠道连接”升级为“连接与账号”，统一管理 QQ、微信和邮件：

- Gmail / Microsoft：显示是否由系统管理员启用；启用后走 OAuth + PKCE。
- SMTP：服务器、端口、安全方式、账号、授权码、发件地址。
- 每个连接展示正常、需重新授权、不可用；支持测试发送和删除。
- 凭据只进入用户隔离的加密连接库，不进入工作流定义、浏览器存储和日志。

## 数据与兼容

- `mcp_query` 继续保存稳定 tool name 和 schema hash，界面通过受控任务映射选择工具。
- `template` 在新界面展示为“发送结果 / 保留在运行记录中”。
- `official_notification` 和 `personal_email` 在新界面展示为同一“发送结果”的不同方式。
- 旧 `mcp_action` 若目录已不存在，保持只读并提示所需能力，不允许静默替换。
- 发布和运行均重新检查工具目录、schema hash、权限、连接所有权和发送确认。
- 运行列表从持久化记录重新读取开始/完成时间，运行结束自动打开详情，并直接展示“发送结果”节点的中文最终正文。
- 所有外部来源返回先检查结构化 `status/code`；鉴权失效、超时、限流和不可用分别映射为稳定工作流错误，不能把 HTTP/MCP 成功信封里的业务失败当成查询成功。

## 验收标准

- 默认界面不出现 MCP、tool name、cron、经纬度、站码、POI ID、JSON 或变量表达式。
- 节点库只出现五个稳定用户入口；空 action 不出现；模板和邮件不重复占节点。
- 获取信息不按来源分组，来源只作为结果可信度信息。
- 没有邮箱系统配置时明确说明管理员需要补什么，不让用户进入必然失败的授权流程。
- 所有已展示能力可以在当前账号下完成测试；能力失效时发布前阻止并给出中文下一步。
- 旧工作流无损打开、保存和运行。
- 最终交付只向用户索取无法由代码生成的 API Key、OAuth 应用、SMTP/测试邮箱或第三方扫码授权。

- 前端节点库收敛为开始、获取信息、智能处理、条件分支、发送结果；无 action 时不展示执行操作。
- 画布四方向按钮的 viewport 位移已检查；节点向下拖动后位置由 `y=256` 变为 `y=352`，再向上恢复。
- 创建并发布“杭州天气摘要验收”，真实执行天气查询、LLM 摘要、发送结果，运行历史显示完成时间和可读最终正文。
- 真实页面测试：杭州天气成功；“西湖景区/杭州”返回 20 个地点；杭州到上海次日车票返回 75 趟；小红书“杭州旅行”返回 10 篇；网页搜索成功返回结果并完成中文摘要适配。
