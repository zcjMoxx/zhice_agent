# 旅行任务并发、地图点位与检索恢复设计

## 背景

旅行规划页在连续使用时暴露出几类相互关联的问题：正在生成的任务会阻止新建计划；删除运行中任务后，后台 Turn 仍可能回写 Session 文件并被索引为 `cli_legacy`；从旅行页带问题返回主聊天时，输入框要等待会话刷新才出现；已完成任务仍可能残留确认按钮或“本次回复已停止”。同时，历史计划缺少坐标时地图无法展示点位，外部检索对“小红书未登录”“空结果”和“Tavily 补充查询超时”的状态表达也不准确。

## 目标

- 允许用户在一个旅行计划后台生成时立即新建独立计划，任务按 Session 并发运行。
- 删除运行中的 Session 前等待其 Turn 完全退出，杜绝会话文件复活和伪 CLI 索引。
- 返回主聊天后立即填入携带的问题，不受会话列表刷新耗时影响。
- 规划中、历史态和完成态不再显示确认规划按钮或陈旧的停止提示。
- 新计划强制每个活动包含可绘制坐标；旧计划缺坐标时由前端地图按地点名补充地理编码。
- 小红书明确区分未登录、空结果和有效结果；空结果只做一次收窄重试。
- Tavily 补充查询串行、有界执行；补充查询超时不丢弃此前已取得的有效资料。

## 范围边界

- 后端既有活动 Turn 键继续使用“用户 + Session”，不引入跨 Session 的全局任务调度器。
- 前端新建计划只脱离当前任务的展示与轮询，不取消后台生成。
- 不共享用户日常浏览器的小红书登录态；只报告并使用只读 MCP 自己的登录状态。
- 历史计划的前端地理编码是兼容措施；新生成计划仍由后端 Schema 和最终化门控保证坐标完整。
- 外部来源重试最多一次，不做无限重试，也不把超时包装成成功。

## 模块设计

### Session 生命周期与并发

`WebRuntime.delete_session` 先捕获活动 Turn，发送取消信号并等待完成事件，再删除 Session 文件和索引。`ActiveTurn` 在注销和关停路径上统一置位完成事件。旅行前端的新建操作清理当前展示状态和恢复轮询，但保留后台 Session；非当前 Session 的终态事件只刷新任务列表并标记完成提醒。

### 主聊天交接与页面状态

主聊天页挂载后先消费旅行交接内容并写入草稿，再异步刷新 Session 列表。确认卡仅在需求收集态、非历史态、非忙碌态显示；进入正式规划和计划完成时清除需求对话错误。

### 地图点位

正式计划 Schema 要求所有活动包含 `longitude` 与 `latitude`，路线折线点统一为坐标对象。规划提示预加载高德地点搜索、地理编码及一项路线能力。对既有无坐标计划，地图组件加载高德后按地点名与行政区进行地理编码，成功的点绘制标记和按日虚线路径，失败时保留文字地点说明。

### 外部来源恢复

来源账本按来源类别记录尝试次数。网页与社区来源只有返回可用条目才记为成功；首次空结果或临时错误标记为需要一次收窄重试，认证失败不盲目重试。小红书适配器在显式空 `feeds` 时检查 MCP 登录状态，未登录返回认证错误。Tavily 补充搜索不在同一模型响应中批量发起；后续超时只标记“补充检索未成功”，已有成功证据继续参与候选方案。

## 数据流

```text
旅行 Session A 后台生成 ──终态事件──> 刷新任务列表
          │
          └─ 用户新建 ──> 旅行 Session B 前台收集需求

地点搜索 ──> 地理编码 ──> 活动坐标 ──> 最终计划校验 ──> 地图标记/路线

外部搜索 ──有效条目──────────────> 成功证据
         ├─首次空结果/临时错误───> 一次收窄重试
         └─认证失败──────────────> 明确提示登录，不盲目重试
```

## 测试方案

- 删除活动 Session 时验证完成事件先于文件和索引删除。
- 验证旅行来源的空结果重试、认证失败不重试、成功后补充超时仍保留成功状态。
- 验证最终计划缺少活动坐标时拒绝保存，路线折线 Schema 使用坐标对象。
- 验证小红书空结果且未登录时返回认证错误。
- 验证生成中可以新建独立计划，后台终态只刷新任务列表。
- 验证主聊天交接内容不等待 Session 刷新、确认卡状态正确、陈旧错误被清理。
- 验证历史活动无坐标时通过高德地理编码生成地图覆盖物。

## 验收标准

- 一个计划生成中仍可新建另一个计划，两个 Session 状态互不覆盖。
- 删除运行中旅行任务后不会新增 `CLI` 会话。
- 返回主聊天后问题立即出现在输入框。
- 已开始或已完成计划不再出现“确认并开始规划”，也不残留“本次回复已停止”。
- 新生成计划的每个活动均有地图坐标，旧计划尽可能补绘地点。
- 小红书未登录、搜索无结果和查询成功在界面上含义准确；空结果最多自动重试一次。
- Tavily 单次补充超时不使此前成功结果失效，候选方案仍使用已有证据生成。
