# MCP 长文本首尾保留设计

## 背景

MCP 文本结果统一限制为 12000 字符，但当前只保留开头。12306 等按时间排序的长列表因此会在持久化 Session 中丢失尾部晚班车；进程重启后旅行来源账本只能从截断结果重新水合，Finalizer 反复看到早班返程车，无法生成与末日活动兼容的计划。

## 目标

- 保持 MCP 单次文本输出 12000 字符上限不变。
- 长文本同时保留开头和结尾，使顺序列表的早期与晚期候选都可恢复。
- 保留明确截断标记和原始、返回字符数元数据。

## 范围边界

- 仅改变 MCP 非结构化长文本的截断策略，不改变普通 Tool、Exec 或上下文压缩。
- 不针对 12306 工具名硬编码业务逻辑。
- 不扩大模型上下文或持久化体积上限。

## 模块设计

`agent/mcp/result.py` 在拼接文本后使用 MCP 专用首尾截断：预算近似均分给头部和尾部，中间插入 `[truncated middle]`。未超限结果保持原样；结构化结果和附件规则不变。

## 数据流

```text
MCP 长文本
  -> 拼接内容块
  -> 超过 12000 字符
  -> 保留头部 + 中间截断标记 + 尾部
  -> ToolResult + truncation metadata
  -> Session 持久化
  -> 重启后可从首尾候选重新水合
```

## 测试方案

- 未超限文本完全不变。
- 超限文本总长度不超过 12000，同时包含原始开头、结尾和中间截断标记。
- `truncated`、`original_chars`、`returned_chars` 元数据准确。
- 现有结构化结果、附件和错误测试保持通过。

## 验收标准

- 新生成的 12306 长结果持久化后仍包含当天末尾车次。
- 服务重启后旅行账本能够恢复晚班返程候选。
- MCP 输出大小和 Secret 边界不放宽。
