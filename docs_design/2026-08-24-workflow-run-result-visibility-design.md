# 工作流运行结果与外发回执可见性设计

## 背景

当前执行记录只能查看节点状态和时间。节点的安全输入、输出摘要已经持久化，但接口没有把它们组织成用户可理解的“本次运行结果”，前端也没有展示；执行记录打开后还不能通过再次点击同一条记录收起。尤其在结果发送到邮箱、SMTP 或 QQ 时，用户只能看到成功状态，无法确认发送了什么以及外部渠道是否接受。

## 目标

- 每次运行都在执行记录中展示结果摘要，不因投递渠道不同而消失。
- 外发节点同时展示内容摘要和投递回执，正文允许截断但不能完全缺失。
- 同一条执行记录支持再次点击收起，切换其他记录时直接展示新记录。
- 继续使用现有脱敏与 4096 字符上限，不在浏览器暴露密钥、令牌或完整凭据。

## 范围边界

- 本次不改变工作流节点类型、投递渠道或执行顺序。
- 本次不保存无限长度的正文或附件；执行记录展示的是脱敏后的有界摘要。
- 历史记录尽量从已有节点摘要生成结果；新运行额外把外发正文写入安全输入摘要，确保直接配置的正文也可回看。

## 模块设计

### 执行与持久化

外发节点执行前生成实际发送的纯文本正文，并将其作为 `content` 加入该节点的安全输入摘要。节点输出继续保存渠道返回的安全回执。两者都沿用 `safe_summary` 的脱敏和长度限制。

### 运行详情接口

`WorkflowStore.get_run()` 在现有 `nodes` 基础上生成顶层 `results`：

- 保留在工作流中的结果：返回最终内容节点的 `content_summary`。
- 邮箱、SMTP、QQ 等外发结果：返回外发节点的 `content_summary` 和 `delivery_summary`。
- 失败投递：保留可取得的内容摘要，并返回节点错误码。

若外发节点存在，以外发节点作为最终用户结果，避免同时重复展示其上游模板节点；没有外发节点时，优先选择最后一个模板结果，必要时回退到最后一个具有输出的业务节点。

### 前端交互

- Store 增加执行详情 toggle：同一记录再次点击时清空详情，其他记录正常加载。
- 详情区顶部渲染“本次运行结果”，正文采用可换行的摘要视图，外发场景追加“投递结果”。
- 下方保留步骤列表，每个步骤可展开查看输入、输出摘要与错误码。

## 数据流

```text
节点生成内容
  -> 外发节点生成实际纯文本正文
  -> 安全输入摘要保存正文
  -> 渠道发送并返回回执
  -> 安全输出摘要保存回执
  -> get_run 组装 results
  -> 执行记录展示内容摘要和投递结果
```

## 测试方案

- 后端：验证外发节点安全输入摘要包含实际正文；运行详情能同时返回内容摘要和投递回执；无外发节点仍返回最终结果。
- Store：验证打开、再次点击收起、切换记录。
- 页面：验证执行结果、外发回执、步骤摘要渲染及点击收起。
- 运行工作流相关单元测试、前端相关测试、类型检查和生产构建。

## 验收标准

- 任意结果处理方式运行后，执行记录中都存在“本次运行结果”。
- 邮箱、SMTP、QQ 记录至少展示有界内容摘要和投递状态/回执。
- 点击已展开的执行记录可以收起，再点击或点击其他记录可正常打开。
- 展示内容保持脱敏，长内容受 4096 字符上限约束。
