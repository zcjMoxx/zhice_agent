# 手机认证页垂直居中与一体化备案页脚设计

> 说明：本记录继续修正《2026-08-25 手机注册页单屏适配与XHS本地回环配置设计》中手机认证卡片贴顶、备案链接独立悬置的布局；旧记录正文保留当时方案原貌。

> 说明：备案页脚的视觉结构继续保留，但真实编号和文案改由《2026-08-25 公安备案信息Private Runtime配置设计》的private runtime接口提供，不再硬编码进前端。

## 背景

前一版已经消除了手机注册页的纵向滚动，但认证卡片仍从视口顶部开始排列，公安备案以独立胶囊悬在卡片下方。两部分视觉上彼此分离，且在较高手机视口中下方留白明显，不符合认证入口应作为一个整体垂直居中的布局预期。

## 目标

- 手机端将认证表单与公安备案组织为同一张视觉卡片。
- 整张卡片在动态视口内垂直、水平居中。
- 备案成为卡片内部的轻量页脚，不再使用独立悬浮胶囊。
- 390×568 等短屏仍完整显示并且不可上下滚动。

## 范围边界

- 只改变认证页的结构容器与手机端样式，不改变备案链接、注册逻辑或桌面端位置。
- 桌面端继续使用现有双栏认证卡片和视口底部备案展示。
- 短屏仍可隐藏装饰性品牌区，但不得压缩表单触控区域。

## 模块设计

- 在 `AuthLayout` 中增加 `auth-surface`，统一包裹 `auth-slider` 与备案页脚。
- 桌面端 `auth-surface` 使用 `display: contents`，维持既有布局行为。
- 460px及以下将 `auth-surface` 渲染为有边框、圆角、背景和阴影的单一视觉表面。
- 手机端认证页改为居中布局；内部 slider 去掉重复边框、圆角和阴影。
- 备案页脚使用卡片内部顶部分隔线，链接取消胶囊背景和阴影。
- 650px及以下继续隐藏注册品牌区，并缩小页面安全边距以容纳一体化页脚。

## 数据流

```text
动态手机视口
  └─ auth-page 居中容器
      └─ auth-surface 单一卡片
          ├─ auth-slider 认证内容
          └─ public-security-record 内嵌页脚
```

## 测试方案

- 更新组件测试，确认备案位于 `auth-surface` 内。
- 更新响应式合同，锁定手机端居中容器和一体化页脚样式。
- 运行前端 lint、typecheck、全量测试与生产构建。
- 用真实浏览器验证390×568、390×700、390×844和430×700注册态的滚动高度、边界与截图。

## 验收标准

- 手机端认证卡片整体垂直居中，顶部与底部留白自然。
- 备案与表单共享同一卡片边界，不再单独悬在卡片下方。
- 所有验收手机视口中`document`和`.auth-page`均无纵向滚动。
- 账号、密码、确认密码、提交、返回登录和备案链接均完整可见。
