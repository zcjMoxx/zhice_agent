# 工作流状态判断与有限重试设计

## 背景

现有条件节点只能比较上游输出值；任一节点失败会立即结束整个运行，用户无法在画布中表达“检查上一步是否成功，失败时有限重试，成功后继续”。工作流图仍必须保持 DAG，不能通过普通连线创建无界环。

## 目标

- 条件节点支持判断一个直接上游节点的执行状态。
- 状态为失败时，可按用户配置重新执行该上游节点，最大尝试次数限制为 1 至 5 次。
- 任一次重试成功后走“是”分支；耗尽次数仍失败时走“否”分支。
- 每次尝试写入独立节点运行记录和事件，便于本地与线上诊断。

## 范围边界

- 只支持重试条件节点的直接上游节点，不支持任意子图回跳。
- 不允许普通图边形成环；现有 `WORKFLOW_GRAPH_CYCLE` 校验保持不变。
- 外发和 MCP 写操作不允许由该机制自动重试，避免重复副作用；第一阶段仅允许 `mcp_query`、`llm_transform`、`template`。
- 本次只在本地实现和验证，不修改服务器工作流或部署。

## 模块设计

条件节点新增配置：

- `check_mode: "value" | "status"`
- `status_node_id`: 要检查的直接上游节点 ID
- `retry_on_failure`: 是否在失败时重试
- `max_attempts`: 包含首次执行在内的最大尝试次数，范围 1 至 5

图校验负责确认目标存在、确为直接上游、类型可安全重试以及次数有界。执行器允许受状态条件保护的节点失败后继续到条件节点，并在条件节点内进行有限重试。重试成功输出覆盖该节点的最新输出；耗尽后保留失败状态并进入“否”分支。

## 数据流

```text
上游节点首次执行
  -> 成功 -> 状态条件=true -> 是分支
  -> 失败 -> 状态条件=false
       -> 未到上限 -> 重试上游节点 -> 重新判断
       -> 到达上限 -> 否分支
```

## 变更文件

- `agent/workflows/catalog.py`：状态条件配置和安全重试边界校验。
- `agent/workflows/executor.py`：受控失败、有限重试和尝试事件。
- `web/frontend/src/pages/WorkflowPage.vue`：状态判断与重试配置入口。
- `tests/unit_test/workflows/test_workflows.py`：成功恢复、耗尽和非法配置测试。
- `web/frontend/src/pages/WorkflowPage.test.ts`：编辑器配置入口测试。
- `tests/unit_test/workflows/test_case.md`：同步测试说明。

## 测试方案

- 第一次失败、第二次成功，最终走“是”分支。
- 连续失败达到上限，最终走“否”分支且每次尝试可见。
- 拒绝非直接上游、超过次数范围和有副作用节点自动重试。
- 原有值比较条件和 DAG 环检测保持兼容。

## 验收标准

- 页面可配置“检查上一步是否成功”和最大尝试次数。
- 自动重试严格有界，不能形成普通图环或重试外发/写操作。
- 运行详情能看到每次尝试及最终分支。
- 后端工作流测试、前端页面测试、Ruff 检查通过。
