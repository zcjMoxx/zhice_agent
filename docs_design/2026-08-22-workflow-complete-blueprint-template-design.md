# 工作流完整蓝图模板设计

> 说明：QQ 主动通知已在同日完成真实链路验证并进入当前代码，模板会在当前用户 QQ 已绑定且渠道在线时优先使用“发送到我的 QQ”；最新出口设计见 `docs_design/2026-08-22-workflow-qq-active-notification-design.md`。本文正文保留当时仅有邮件出口的方案背景。

## 背景

工作流模板不是创建前的填写向导。用户点击模板时，应该直接得到一份节点和连线都已经搭好的普通工作流草稿，再进入真实画布逐个补齐必填项。现有天气和信息摘要模板只搭到智能处理，缺少结果出口，也没有在画布上明确标记待配置节点。

## 目标

- 模板点击后直接创建并打开完整画布，不增加任何前置表单。
- 每份模板包含触发、获取、处理和结果出口的全部节点与连线。
- 模板创建的节点与空白画布节点完全一致，允许移动、修改、删除、重新连线和继续扩展。
- 待配置节点在画布和详情面板中清晰标识；顶部清单可以点击定位。
- 天气模板内置可编辑的穿衣、带伞和出行建议规则。

## 范围边界

- 模板只是可复制蓝图，不引入独立执行协议、隐藏节点或不可编辑配置。
- 邮箱账号、收件人、地点和执行时间不由模板猜测，进入画布后由用户填写。
- 当前只展示已经存在真实运行能力的节点；QQ/微信主动通知在对应工作流出口完成前不伪装为可选项。

## 模块设计

1. `workflow-templates.ts` 维护模板元数据、完整节点和连线，并在实例化时绑定当前真实 Tool schema hash。
2. 天气模板固定为“每天定时 → 查询天气 → 生成今日建议 → 发送结果”，发送结果使用当前已走通的个人邮箱节点，但账号和收件人留空。
3. 每日信息摘要同样补齐邮件结果节点，不再停在整理步骤。
4. 配置检查改为结构化条目，每条问题记录所属节点；画布节点显示“待配置”，顶部问题可点击打开对应节点详情。
5. 智能处理增加“生成生活建议”预设，允许选择雨具、穿衣、出行主题以及通勤方式、体感偏好和补充要求。
6. 节点内容自身显式响应按下，并提供不参与拖拽的“编辑节点”按钮，避免只依赖画布库事件而出现节点可见但无法编辑。

## 测试方案

- 断言每份模板都包含触发、信息获取、智能处理和结果出口，且全部节点由边连接。
- 断言模板实例化会写入当前 Tool schema hash，并保持时间、地点、邮箱账号和收件人为待填写状态。
- 运行前端 Lint、TypeScript、Vitest 和生产构建；浏览器验证模板卡片和完整画布，不触发真实邮件。

## 验收标准

- 点击天气模板后直接看到四个已连好的节点。
- 开始、查询天气和发送结果清楚显示待配置，点击顶部问题能定位节点。
- 点击任意画布节点都能切换右侧节点详情，节点拖动和连线操作保持独立。
- 用户无需离开画布即可填写全部必要内容，且可自由改造模板。
- 发布和立即运行在必填项完成前保持禁用。
