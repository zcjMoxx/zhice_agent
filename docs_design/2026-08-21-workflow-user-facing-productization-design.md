# 工作流用户化文案与产品体验优化设计

> 日期：2026-08-21
>
> 状态：已实施并通过真实浏览器验收
>
> 关联：`2026-08-21-workflow-overview-detail-navigation-design.md`、`zhice-agent-part20-visual-workflow-scheduler-design.md`

## 背景

真实浏览器按普通用户路径验收后，工作流页面仍暴露大量实现标识：工具下拉展示 `mcp__server__function`，参数表单展示 `date`、`fromStation` 等 schema key，画布展示 `manual`，总览与运行历史展示 `draft`、`succeeded`、run ID、node ID 和 error code。编辑器还直接使用 `AUTOMATIONS / EDITOR`、`NODE LIBRARY`、`Inspector`、`Tool Schema` 等工程术语。

新增查询节点会自动选择目录中的第一个工具，造成用户尚未选择却看似已经配置完成。发布和运行按钮可能因工具缺失或动作确认而禁用，但页面没有集中说明缺少什么；工具的必填参数未在前端纳入就绪判断。总览卡片把进入详情与删除交互嵌套在同一个按钮中，键盘和点击语义不够清晰。

## 目标

- API、持久化和 schema hash 继续使用稳定内部值；普通界面只显示中文产品名称。
- 当前 12306、高德地图、Open-Meteo、Tavily、小红书工具有明确中文名称和服务来源；未来未知工具也不直接裸露 `mcp__` 标识。
- Schema 字段显示中文名称、中文说明和必填状态；内部 key 只在显式展开的高级 JSON 中出现。
- 工作流、运行、节点、触发方式和错误状态统一显示中文。
- 新节点不自动选择第一个外部工具，必须由用户明确选择。
- 集中展示发布就绪状态，指出未选工具、参数未填、工具规则变化和动作确认等具体阻塞项。
- 总览打开与删除成为相邻但独立的语义按钮，避免嵌套交互。

## 范围边界

- 不修改 Tool name、WorkflowDefinitionV1、参数 key、schema hash 或后端执行协议。
- 不伪造工具能力；中文名称只是表现层映射，选择后仍以原始 name 调用真实工具。
- 高级 JSON 面向熟悉协议的用户，允许展示原始 key；默认表单与普通状态区域不展示内部标识。
- 本轮不新增外部依赖，不改变 RBAC、发布、调度或动作确认安全边界。
- 账号创建仅在现有登录态无法覆盖普通用户路径时使用；若需最终提交注册，遵循浏览器动作确认要求。

## 产品设计

### 中文表现层

新增纯函数模块集中维护：

- 工具服务名、工具动作名与未知工具降级名称；
- Schema 字段中文名和从中文 description 提取的安全降级；
- 工作流状态、运行状态、节点状态、触发方式、节点类型、错误码文案；
- 中文日期时间和版本文案。

页面只调用这些函数，不在模板中散落枚举判断。工具选项按服务来源分组，选项显示“功能名称”，分组标题显示“12306 / 高德地图 / 天气服务 / 网页搜索 / 小红书”。选中后展示来源、类型和中文说明。

### 明确配置与就绪检查

新建外部工具节点时 `tool_name` 为空，不再默认绑定目录第一项。就绪检查遍历所有外部工具节点：

1. 是否已选择当前用户可用工具；
2. schema hash 是否仍匹配；
3. schema required 字段是否存在且非空；
4. 外部动作是否完成影响确认。

顶部显示“可以发布”或“还需完成 N 项”，点击/阅读即可看到具体阻塞文案。发布和立即运行继续使用相同前置条件，后端仍做最终权威校验。

### 总览与运行历史

总览状态改为“草稿 / 已发布 / 已暂停 / 需要处理 / 已归档”，“v1”改为“版本 1”。品牌分区标题根据当前语言显示中文或英文。工作流卡片使用独立的打开按钮和删除按钮。

运行历史隐藏默认无意义的 run ID，显示“手动触发 / 定时触发”、中文状态和本地时间。节点时间线用工作流节点名称或中文节点类型替代 node ID；错误码转为可操作的中文说明，内部 code 不作为主文案。

## 测试方案

- 表现层单测覆盖已知工具、未知工具降级、字段中文名、所有状态、触发方式和错误码。
- 编辑器工具节点默认未选择；必填参数缺失进入阻塞项，填写后解除。
- lint、typecheck、完整 Vitest 和 production build 全部通过。
- 真实浏览器从总览打开草稿，添加查询节点，检查工具分组、中文选项、中文字段、就绪提示和画布摘要。
- 检查普通页面 DOM 不出现 `mcp__`、`draft`、`manual`、`NODE LIBRARY`、run/node 内部 ID；高级 JSON 不纳入此断言。
- 使用现有账号完成保存前的无副作用路径；只有现有身份无法覆盖授权边界时才创建测试账号。

## 验收标准

- 普通用户无需理解 MCP 命名、schema key 或状态枚举即可完成配置。
- 新节点不会未经用户选择就绑定工具。
- 按钮禁用时页面明确告诉用户下一步做什么。
- 总览、编辑器、运行历史保持中文产品语义，内部值仍可稳定往返 API。
- 真实浏览器主路径、完整前端测试和生产构建通过。

## 实施与验收结果

- 普通中文界面已统一展示工具、服务来源、字段、状态、触发方式、节点类型、版本、时间和错误的用户文案；原始 Tool name、schema key、run/node ID 与错误码只保留在协议或显式高级配置中。
- 新建外部工具步骤保持未选择状态，工具按来源分组；选择后展示服务来源、只读/外部操作属性、中文参数名和无内部接口名的填写提示。
- 画布和运行历史集中展示配置阻塞项；必填参数补齐后，“可以发布”、发布按钮和立即运行按钮同步解除阻塞。
- 总览列表和卡片的打开、删除使用独立按钮；编辑器顶部操作保持单行，避免中等宽度下按钮断行。
- 真实浏览器检查普通 DOM 不含 `mcp__`、`draft`、`manual`、`NODE LIBRARY`、`Inspector`、`Tool Schema`、`station_code` 和内部日期接口名。
- 前端 `lint`、`typecheck`、181 项 Vitest 与 production build 全部通过。
