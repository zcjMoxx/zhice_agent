# 工作流与旅游规划交互清晰度修正

## 背景

工作流画布的系统手掌光标与产品绿色指针不一致，连线缺少方向提示，编辑栏遗漏启停入口，且保存、发布、运行的用户语义不清。旅游规划入口不够明显，需求对话中的用户标签错位；同名地点还可能让正式规划在错误地点上进行昂贵查询。

## 目标

- 画布使用系统张开/闭合手掌光标，不内置颜色或形状；节点保持系统指针手势。
- 连线用闭合箭头表达从源节点到目标节点的方向，不增加节点编号。
- 工作流首页介绍本身使用圆弧形说明盒，不增加跳转入口。
- 恢复已发布工作流的启用/停用开关，并明确草稿、发布启用、单次试运行的差异。
- 手动保存成功后持续显示明确反馈；关闭节点详情后不再保留脱离节点的画布入口。
- 用户消息不重复显示“你”；“智策旅行顾问”独占一行，回复气泡使用整行宽度。
- 同名或无法唯一定位的地点先追问；未解决前服务端禁止确认规划，刷新后仍保留阻塞状态。

## 范围边界

不改变工作流定义协议、节点执行顺序或调度器边界；“立即试运行”保存当前草稿后只执行该草稿，不发布、不改变线上版本或启停状态。不维护易过期的同名地点硬编码表，由接待模型识别不确定性，服务端持久化并强制执行未澄清阻塞。正式规划 Prompt 保留第二道地点歧义兜底。

## 模块与数据流

工作流页面向 Vue Flow 的默认边配置注入 `ArrowClosed`，自定义边继续透传 marker。编辑栏直接调用现有 pause/resume API。首页介绍放入不可点击的圆角说明盒。单次试运行先保存草稿，再调用独立 `run-draft` 接口；该接口执行最新草稿，但不写入发布版本、不改变 `active_version` 或启停状态。

用户点击编辑栏“保存草稿”后，按钮在请求期间显示“保存中…”，成功后短暂显示“已保存到工作流”；只有手动保存显示这条确认，返回、切换工作流等隐式保存不额外打断操作。节点详情只通过点击节点或节点内编辑按钮打开，移除画布右上角独立的“节点详情”入口。

旅行接待模型通过 `update_travel_draft.location_clarifications` 写入全部未解决地点问题；Tool 将其保存到 Session metadata，并把 `ready` 计算为“核心字段齐全且地点无歧义”。运行事件和草稿恢复 API 把问题传到前端，前端隐藏确认入口。`confirm_and_start_travel_planning` 在服务端再次校验并返回 `TRAVEL_LOCATION_CLARIFICATION_REQUIRED`。用户明确补充上级行政区后，模型更新地点并清空问题，才允许确认。

## 变更文件

涉及工作流页面、样式、独立草稿试运行 API 和页面测试；旅行 Tool、运行时草稿投影、API schema、前端类型/store/form、接待与正式规划 Prompt，以及旅行单元测试与测试说明。

## 测试方案

- 工作流页面测试：箭头默认配置、旅游入口、按钮文案和启停入口。
- 工作流保存交互测试：保存 API 成功后显示“已保存到工作流”，且关闭详情后不出现独立入口。
- 旅行 Tool 测试：歧义持久化、ready=false、明确澄清后恢复 ready、确认阶段强制拒绝。
- 前端旅行测试：地点歧义存在时不显示确认入口；事件与刷新恢复投影正确。
- 运行 Python Ruff/目标 Pytest，以及前端测试、ESLint、TypeScript 构建。

## 验收标准

画布手掌遵循系统样式且按下切换闭合状态；每条工作流线有明确箭头；首页可进入旅游规划；已发布工作流可直接启停；保存草稿成功有明确反馈，关闭节点详情后不出现独立入口；保存草稿、发布启用和不发布的单次试运行互不混淆；“你”位于右侧；含同名地点的不完整需求不会开始外部研究，刷新也不会丢失待澄清状态。
