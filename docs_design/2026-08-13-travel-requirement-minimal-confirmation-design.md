# 旅行需求最小确认设计

> 说明：本文的最小阻塞字段和固定节日补全仍有效；后续交互已改为卡片内多轮问答补全，右上角“补充数据”仅作为不调用 LLM 的手工表格入口，见 `2026-08-13-travel-conversational-requirement-review-design.md` 与 Part 19 活文档。

## 背景

当前需求确认把同行人群、人数、节奏和规划模式全部视为红色阻塞项；同时模型可能没有把“国庆期间，玩 5 天”换算成具体日期。用户已经清楚表达时间窗口、出发地、目的地和天数，却仍被要求补齐大量执行选项，确认成本过高。

## 目标

- 固定日期节日与明确天数可确定性换算时自动补齐日期。
- 只阻塞无法安全执行的核心信息，不把执行策略当作用户需求错误。
- 未表达的人群使用中性“旅行者”标签；节奏和规划模式使用透明执行策略，不冒充模型提取结果。

## 边界

- 只解析日期固定且无歧义的中国节日：元旦、劳动节/五一、国庆；春节、中秋等农历节日不在无日历服务时猜测。
- “期间 + N 天”从固定节日首日开始，结束日期包含最后一天。
- 若本年度节日已过，选择下一次节日；显式年份始终优先。
- 人数仍是核心容量与预算输入，未表达时需要用户确认，不静默猜 1 人。
- 默认节奏 `balanced`、模式 `quick` 是系统执行策略，提交时明确标注为系统假设，用户仍可修改。

## 测试与验收

- 参考日期 2026-08-13，“国庆期间，重庆出发到云南大理游玩5天”得到 2026-10-01 至 2026-10-05。
- 页面只提示确认人数；同行人群、节奏、规划模式不出现在红色缺失列表。
- 补充人数后可开始规划，提交文本明确区分用户表达和系统执行策略。
