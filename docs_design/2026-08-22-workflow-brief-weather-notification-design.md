# 工作流天气提醒精简设计

## 背景

“每日天气建议”已经能够按时查询地点天气并发送到用户 QQ，但模板默认要求逐项说明带伞、穿衣、出行、避开时段和所有天气风险，同时把结果长度设为“适中”。这会把日常提醒生成成完整天气报告，不符合消息通知应当一眼读完的使用场景。

## 目标

- 默认生成最多 3 行、约 90 个汉字的天气提醒。
- 只提醒当天实际有用的事项，不逐项声明不存在的风险。
- 保留用户在节点中选择“简短、适中、详细”的能力，并让每档长度都有明确上限。
- 同步更新已经发布的用户天气工作流，使下一次定时执行直接采用精简规则。

## 范围边界

- 不改变天气查询来源、地点解析、调度时间和 QQ 发送链路。
- 不自动触发工作流，不发送测试 QQ 消息。
- 不截断其他类型的智能处理结果；仅收紧“生成生活建议”节点的表达规则。

## 模块设计

### 模板默认值

“每日天气建议”的智能处理节点默认选择“简短”。生成内容按以下顺序组织：

1. 一句话概括天气；
2. 一句话给出今天真正需要的带伞、穿衣或出行建议；
3. 只有存在明显风险时才增加风险提醒。

### 编辑器规则

用户切换结果长度后，节点内部指令同步使用明确上限：简短最多 3 行/90 个汉字，适中最多 5 行/180 个汉字，详细最多 8 行/350 个汉字。所有档位都禁止为了完整而罗列不存在的风险。

### 已有工作流

对当前已经发布的“每日天气建议”保存一个新版本，仅修改智能处理节点的长度和指令。旧版本继续保留在版本表中，调度、地点、授权和发送方式保持不变。

## 数据流

```text
天气事实 -> 精简生活建议 -> QQ 纯文本提醒
```

## 测试方案

- 单元测试验证天气模板默认选择“简短”。
- 单元测试验证默认指令包含 3 行/90 字限制，并禁止罗列不存在的风险。
- 运行前端测试、类型检查、代码检查和生产构建。
- 只读核对运行态工作流新版本、调度时间、地点和 QQ 发送节点未发生意外变化。

## 验收标准

- 新建天气模板默认使用精简提醒规则。
- 已发布用户天气工作流的下一次执行使用相同精简规则。
- 不产生新的真实 QQ 消息或工作流运行记录。
