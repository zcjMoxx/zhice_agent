# 密码可见性按钮键盘流修正设计

## 背景

密码可见性切换第一版将眼睛实现为普通 button。它在 DOM 中紧跟输入框，因此会进入键盘 Tab 顺序，导致用户在字段之间推进时先落到眼睛按钮。部分 Edge 环境还会同时显示原生 `::-ms-reveal` 和自定义按钮，造成一个输入框看见两个眼睛。

用户期望 Tab 在表单输入框之间直接推进到下一个字段；眼睛仅作为稳定的鼠标或触屏显示/隐藏控件，不干扰日常填写路径。

## 目标

1. 自定义眼睛不进入 Tab 顺序，但仍可点击切换可见性。
2. 隐藏 Edge 原生 reveal/clear 控件，保证每个敏感输入框只显示一个眼睛。
3. 动态管理员创建用户表单复用相同行为。
4. 不改变 Enter 提交和浏览器默认表单键盘行为。

## 范围边界

- 不改变点击眼睛后显示/隐藏密码的行为。
- 不修改后端认证、密码提交、表单校验或 autocomplete。
- 不为眼睛增加新的全局快捷键。
- 不拦截聊天输入框的 Enter 行为。

## 模块设计

- `index.html` 与动态管理员表单：所有眼睛按钮设为 `tabindex=-1`。
- `app.js`：动态管理员表单创建时保持眼睛按钮的非 Tab 设置。
- `styles.css`：隐藏 `::-ms-reveal` / `::-ms-clear`，保留自定义按钮。
- 静态资源 JS/CSS query version 更新。

## 测试方案

| 用例 | 预期 |
|---|---|
| 静态眼睛按钮 | 所有静态及动态眼睛都有 `tabindex=-1` |
| 原生眼睛 | CSS 隐藏 `::-ms-reveal` 和 `::-ms-clear` |
| 浏览器 | Tab 直接跳过眼睛，Enter 保持浏览器默认表单行为 |

## 验收标准

1. Tab 填写路径不会停在眼睛按钮。
2. 任一密码框只显示一个自定义眼睛。
3. 动态管理员创建用户表单同样适用。
4. JS 语法、Ruff、浏览器验证和全量测试通过。
