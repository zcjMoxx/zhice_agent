# 工作流个人邮箱友好连接设计

## 背景

现有个人邮箱表单把 SMTP 服务器、安全方式、端口和发件地址全部直接展示给普通用户。用户通常只知道自己的邮箱地址和服务商生成的授权码；发件地址实际又与邮箱账号相同，重复填写既增加理解成本，也容易填错。

## 目标

- 普通用户只需选择邮箱类型、填写邮箱地址和授权码。
- QQ、网易 163、网易 126 自动使用安全的服务器配置。
- 其他或企业邮箱保留完整能力，但只在用户明确选择时展示服务器设置。
- 发件地址始终由后端使用邮箱账号生成，不再成为用户输入或公开 API 字段。
- 保持现有按用户加密隔离、验证连接、测试发送、删除连接和工作流调用链不变。

## 范围边界

- 保留个人 SMTP，不恢复 Gmail 或 Microsoft OAuth。
- 不接受网页登录密码，继续要求邮箱服务商生成的 SMTP 授权码。
- 不改变平台官方通知邮箱的 `ZHICE_SMTP_*` 独立配置。
- 不伪造真实发送完成状态；仍以服务商接受和实际收件共同验收。

## 模块设计

### 设置页

表单默认选择 QQ 邮箱，只展示：

1. 邮箱类型：QQ、网易 163、网易 126、其他或企业邮箱。
2. 邮箱地址：同时作为登录账号和发件地址。
3. 邮箱授权码：明确提示不是网页登录密码。

已知服务商的服务器、安全方式和端口由前端预设，不展示技术字段。选择“其他或企业邮箱”后，才展示发信服务器、连接方式和端口，并提示向邮箱管理员索取。

### API 与运行时

创建连接请求不再接受 `from_address`。`ConnectionRuntime` 规范化邮箱账号后，将其同时用于 SMTP 登录、邮件 From 头、连接展示名和加密凭据中的发件地址，防止不同入口产生不一致。

### 数据流

```text
选择邮箱类型 + 邮箱地址 + 授权码
  -> 已知服务商自动补全安全连接参数
  -> 其他邮箱由用户填写管理员提供的服务器参数
  -> API 不接收发件地址
  -> Runtime 以邮箱地址生成发件地址
  -> 验证登录并按用户加密保存
```

## 变更文件

- `web/frontend/src/components/SettingsCenter.vue`：重做个人邮箱表单与服务商预设。
- `web/frontend/src/styles/app.css`：补充提示和其他邮箱设置样式。
- `web/frontend/src/api/client.ts`：移除公开请求中的发件地址。
- `agent/app/api/connection_routes.py`：收口创建连接请求模型。
- `agent/connections/runtime.py`：由邮箱账号统一生成发件地址。
- `tests/unit_test/connections/`、`web/frontend/src/components/SettingsCenter.test.ts`：覆盖派生逻辑、预设和界面隐藏。
- `README.md`、Part 20 活文档：同步当前产品口径。

## 测试方案

- 后端单元测试验证账号会被同时用作展示名和加密凭据中的发件地址。
- 前端组件测试验证默认不出现 SMTP 技术字段和“发件地址”，QQ 预设生成正确请求，选择其他邮箱才展示服务器设置。
- 运行 Ruff、相关 Pytest、前端测试、ESLint、TypeScript 检查和生产构建。
- 在真实页面以普通账号检查表单交互；真实授权码可用时再完成服务商连接与实际收件验收。

## 验收标准

- QQ/163/126 用户无需理解 SMTP、TLS、端口或发件地址。
- 页面不再要求重复填写发件地址。
- 其他或企业邮箱仍可配置安全 SMTP。
- 连接凭据继续按用户加密隔离，工作流定义不包含授权码。
- 自动化检查全部通过，生产静态资源可正常加载。
