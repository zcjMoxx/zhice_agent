# 工作流启停开关与版本冲突恢复设计

## 背景

工作流编辑页只显示“暂停/恢复”动作按钮，页面状态又会被“未保存修改”覆盖，用户无法直接判断工作流是否正在按计划运行。同时，当工作流已在其他页面或后台更新时，旧页面保存会触发 `WORKFLOW_DRAFT_CONFLICT`，前端此前把它展示成通用的执行失败，容易误以为天气查询或 QQ 发送失败。

## 目标

- 在编辑页和总览页直接显示“已开启 / 已关闭 / 未开启”。
- 编辑页使用可识别的开关控制自动运行，不再依赖“暂停/恢复”的反向动作文案。
- “未保存修改 / 有修改待发布”与运行状态同时展示，互不覆盖。
- 保存当前画布遇到版本冲突时，自动读取最新版本并重试一次，保留用户当前画布。
- 无法恢复的冲突展示明确中文原因，不再误报为节点执行失败。

## 范围边界

- 不改变发布、暂停、恢复和调度的后端语义。
- 不自动运行工作流，不发送 QQ 消息。
- 自动冲突恢复仅在用户主动保存、发布或立即运行当前画布时执行一次；其他错误不重试。

## 模块设计

### 状态表达

- `active`：已开启，会按计划自动运行。
- `paused`：已关闭，不会自动运行。
- `draft`：未开启，发布后开始使用。
- `paused_attention`：已关闭，需要先处理配置问题。

运行状态作为主状态展示；画布变更状态另用“未保存修改”或“有修改待发布”标签展示。

### 启停交互

已发布工作流在顶部显示标准开关。开关开启时点击会暂停调度，关闭时点击会恢复调度。按钮提供 `role="switch"` 和 `aria-checked`，保证键盘和辅助技术可识别。

### 版本冲突恢复

保存接口返回 `WORKFLOW_DRAFT_CONFLICT` 时：

1. 读取服务器最新工作流版本；
2. 保留用户当前画布、名称和配置；
3. 使用最新版本号重新保存一次；
4. 若再次冲突或读取失败，再向用户展示明确提示。

## 数据流

```text
用户保存当前画布
  -> 版本一致：保存成功
  -> 版本冲突：读取最新版本 -> 当前画布基于最新版本重试 -> 保存成功/明确报错
```

## 测试方案

- 单元测试验证版本冲突后读取最新版并保留当前画布重试。
- 单元测试验证工作流状态和冲突错误均使用明确中文。
- 运行完整前端测试、ESLint、类型检查和生产构建。
- 只读核对运行态工作流仍为开启状态、调度仍有效，且没有新增运行或 QQ 发送。

## 验收标准

- 用户无需推断即可看出工作流当前是否启用。
- 开关可以明确关闭和重新开启自动运行。
- 未保存修改不会遮住启停状态。
- 后台或其他页面更新后，用户主动保存当前画布不会出现误导性的“执行失败”。
