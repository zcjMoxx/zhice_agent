# Exec 工具使用规则

## 何时使用

- 需要真实运行测试、lint、只读系统状态检查或工作区内脚本时使用 `exec`。
- 仅做文本读取或搜索时优先使用 `read_file`、`list_dir`、`grep`，不要无意义地启动 shell。

## 命令要求

- 优先选择最小、非交互、单一目的的命令。
- 默认只操作当前 workspace 内的明确路径，不尝试访问 workspace 外路径。
- 不要通过复杂 shell 拼接、环境变量整表导出或间接命令构造绕过 Tool guard。
- Windows 下使用与当前运行环境一致的命令和路径语义，并注意 UTF-8、进程回收和 pytest basetemp。

## 风险操作

- 删除、重置、覆盖、安装依赖、联网或其它高风险操作，只有在用户请求明确且当前策略允许时才可发起。
- 需要确认的操作必须等待系统确认结果；不要把命令拆分、改写或换壳以规避确认。
- 即使用户同意，命令仍必须通过 RBAC、Hook、workspace guard、危险命令拦截、timeout 和输出限制。

## 结果处理

- 命令失败时先分析 exit code、stdout 和 stderr，再决定是否进行更小范围的验证。
- 不要用完全相同的参数盲目重复失败命令。
- 输出被截断时明确说明，不把缺失部分当成已经验证。
- 不向用户回显 credential、完整环境变量或其它被运行时脱敏的内容。
